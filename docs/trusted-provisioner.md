# Trusted provisioner

Lets one trusted workload create organizations without a browser sign-up or a
stored secret. The workload proves who it is with a short-lived identity token
from any OpenID Connect issuer, such as Google Cloud, GitHub Actions or Render.
Off unless all four settings below are set.

## Settings

| Variable | Meaning |
| --- | --- |
| `TRUSTED_PROVISIONER_ISSUER` | The issuer to trust, as an https URL. Its signing keys are found through `/.well-known/openid-configuration`. For Google service accounts use `https://accounts.google.com`. |
| `TRUSTED_PROVISIONER_AUDIENCE` | The audience the identity token must be minted for. Use this instance's provisioning URL. |
| `TRUSTED_PROVISIONER_SUBJECTS` | Comma-separated `sub` values of the trusted workloads. For a Google service account this is its numeric unique ID, not its email, so a recreated account is not trusted. |
| `TRUSTED_PROVISIONER_OWNER_EMAIL_DOMAIN` | The only domain owners can be created on. Use a domain reserved for this, such as `demo.example.com`. See below. |

The instance must also run with `ALLOW_MULTIPLE_ORGS=true`.

### The owner email domain

A verified user can join any organization that allows their email domain. So
the owner domain must be one that no organization allows, that no person has an
address on, and whose mail nobody outside your control can read: whoever reads
an owner's mail can reset its password. The endpoint refuses to run while any
organization allows the domain.

## Request

```
POST /api/v1/provisioning/organizations
Authorization: Bearer <identity token>

{
  "organizationName": "Acme",
  "ownerEmail": "acme-x7k2@demo.example.com",
  "ownerPassword": "<generated by the caller>"
}
```

The response holds `organizationUuid` and `userUuid`. No token is returned.
The caller logs in as the owner with the password it supplied, and mints
tokens as short as it needs.

## Checks

1. The token is signed by the configured issuer, has the configured audience,
   and was issued in the last 5 minutes.
2. Its `sub` is in the trusted list.
3. The organization name, owner email and password are valid. The owner email
   is on the configured domain.
4. The token has not been used before. Mint a new one for every call. A request
   that fails an earlier check does not use the token up.
5. The owner email is not already registered.

The owner is created, then the organization, and the owner's email is marked
verified last. If the organization cannot be created, the owner is deleted.

The endpoint handles at most 30 requests a minute per server process.

## Errors

| Status | Meaning |
| --- | --- |
| 400 | The organization name, owner email or password is not valid. |
| 401 | The token is missing or failed a check. The reason is in the server log only. |
| 403 | The instance allows one organization only, or an organization allows the owner email domain. |
| 404 | The feature is not configured. |
| 409 | The owner email already exists. Either an earlier call created it, or someone signed up with that address; sign-up is open, so the account may be unverified and not yours. Use owner addresses that cannot be guessed. |
| 429 | Too many requests in the last minute. |
